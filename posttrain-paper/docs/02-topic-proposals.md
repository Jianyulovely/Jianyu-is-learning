## P1（推荐）：What Do You Buy with 10 GPU-Hours?
### A Compute-Matched Study of Post-Training at Small Scale

### 要证明的那句话（claim）

> 在 0.5B–3B 规模、固定 GPU 时间预算下，**推理侧计算（自洽投票）在数学推理上的每 GPU 小时收益高于训练侧后训练（SFT/RFT/DPO）**；而训练侧的优势集中在**格式与指令遵循**上。因此「小模型该不该后训练」这个问题没有统一答案，取决于你把算力花在哪个环节。

这句话的价值在于：它把「方法比较」换成了「**预算分配**比较」。方法比较已经红海，预算分配在 1.5B 这个点上还没人系统做。

### 设计（关键：一次采样，三处复用）

```
                    ┌─→ RFT：只保留答对的轨迹 → 再做 SFT
 种子模型 ──采样 K=8 ─┤
                    └─→ DPO：答对/答错配成偏好对 → 做 DPO
                    └─→ 自洽投票：直接对 K 个答案投票（不训练）
```

这一张图是整个方案能便宜的原因：**采样只付一次钱，喂三个方法。**
如果不这么设计，光采样就要跑 3 遍，预算直接翻三倍。

| 变量 | 取值 |
|---|---|
| 模型 | Qwen2.5-0.5B-Instruct、Qwen2.5-1.5B-Instruct（两个点撑起一个 mini scaling 轴） |
| 训练数据 | GSM8K train + MATH train 子集，共 3,000 prompt |
| 评测 | GSM8K test (1,319)、MATH-500、格式合规率 |
| 方法 | SFT(gold) / RFT / DPO / 自洽投票 / 不训练的 prompt-only |
| 预算 | 每条曲线 5 / 15 / 30 / 60 分钟四个点（用训练步数控制） |
| 种子 | 2 个（42, 1234），**必须两个**，否则审稿人一句「seed noise」就否了 |

### 预算核算（这是本文最该做严谨的地方）

审稿人一定会问「你怎么算 GPU 小时」。做法：

- 记录每个阶段的 `wall_clock × device_count`，单位 GPU·h；
- 生成阶段按 **实际吞吐** 折算，不要用理论峰值；
- 明确说明：**评测时间不计入预算**（评测对所有方法一样），但**采样时间计入**；
- 每个方法都跑到相同的预算点，用 learning rate schedule 的总步数来卡预算，不要「跑到收敛为止」。

这一步做扎实，论文的方法学可信度就立住了；做不扎实，整篇就是「我们又跑了个实验」。

### 算力预算

因为**按预算封顶**，成本是可预测的：一个 run 花多少，就等于它被分配了多少。

| 阶段 | 估算 | 说明 |
|---|---|---|
| 训练 | ~33 GPU·h | 3 方法 ×（5+15+30+60 分钟）× 2 种子 × 3 模型 |
| 采样 | ~6 GPU·h | 3000 prompt × K=8，三个模型各跑一遍 |
| 评测 | ~11 GPU·h | 72 个 adapter × 2 个测试集（可用多卡并行） |
| **合计** | **~50 GPU·h** | 单卡约两天 |

**50 小时 = 你那张卡连跑两天**，而且训练和评测可以拆到不同机器上并行。
这是它比另外两个方案更值得做的原因：真的做得完。

### 预期结果与「万一不如预期」

三种可能，**每种都能写成论文**，这是选这个题最大的安全感：

1. **自洽投票赢**（最可能）→ 论文标题就是结论，直接可用。
2. **SFT/RFT 赢** → 同样成立，改成「小模型上后训练仍是更划算的投资」，配一张预算-收益曲线。
3. **两者接近但方差巨大** → 变成「预算分配的收益差异在你的噪声范围内」，配合 seed 分析，是一篇诚实的负结果。

**没有一种结果是「白跑」。** P2 和 P3 没有这个性质。

### 目标 venue（按难度）

1. NeurIPS / ICLR / ACL / EMNLP 的 **workshop**（最现实，接受率 40–60%）
2. ACL/EMNLP **Findings**
3. CCF-C 会议（NLPCC、CCL、ICIC 等）
4. 中文核心 / EI 期刊（如果你只需要「有篇论文」）

### 主要风险与应对

| 审稿意见 | 应对 |
|---|---|
| 「只有 1.5B，不能推广」 | 明确把 claim 限定在 small-scale；加 0.5B 撑出趋势；讨论 7B 的外推作为 limitation |
| 「自洽投票是已知的」 | 不是比谁新，是比**每 GPU 小时的边际收益**，且给出交叉点 |
| 「DPO 没调好」 | 所有方法的超参在同一预算下做相同数量的搜索，附录全列 |
| 「seed 太少」 | 2 个是下限；如果 0.5B 便宜，就上 3 个 |

## P2：Format, Not Reasoning?
### How Much of Post-Training Gains on Math Benchmarks Is Answer Extraction

### claim

> 在小模型上，相当一部分被报告为「推理能力提升」的增益，实际上来自**输出格式合规率**的提升（模型学会了把答案放进 `\boxed{}` 或最后一个数字），而非解题正确率的提升。用严格解析器重评后，增益显著缩水。

### 做法（很便宜）

1. 训 4 个模型：prompt-only / 只学格式的 SFT（训练数据是「同格式但错答案」）/ 正常 SFT / RFT。
2. 用**三套解析器**评测：宽松（正则抓最后一个数字）、标准（`\boxed{}`）、严格（要求完整推理链且答案正确）。
3. 报告「宽松 − 严格」的差值，即格式红利。

### 为什么可能被拒

这类论文容易被读成「你在说别人造假」。必须写得**建设性**：不说谁错了，而是说「评测解析器是后训练结论的一个隐藏变量，建议以后同时报严格指标」。措辞一歪就凉。

### 算力
~8 GPU·h。四个模型都是 1.5B + LoRA。

## P3：领域后训练（最稳，最不亮）

### claim

> 用 3k 条合成/精选领域数据对 1.5B 做 LoRA 后训练，在该领域的任务上超过大得多的通用模型，且成本低于 XX 美元。

### 为什么它「稳」

- 只要数字比 baseline 好，故事就成立；
- 应用类 venue 对新颖性要求低；
- 交付物实在：一个数据集 + 一个 adapter + 一份评测。

### 为什么它「不亮」

- 审稿人一眼看出是「工程报告」；
- 顶会基本无望，别浪费时间投 ACL；
- 如果领域选得不好（比如又是法律/医疗），会被说「又一个领域适配」。

### 适合你的条件
- 你有一个**别人没有的数据源**（实习公司、实验室、自己爬的）——这时 P3 反而最强，因为别人复制不了；
- 或者你的硬要求只是「毕业要有篇论文」，不挑 venue。

### 算力
~6 GPU·h。

```
你有没有独家领域数据？
├─ 有 ──────────────→ P3（独家数据是护城河，别浪费）
└─ 没有
   ├─ 你更怕「做不出来」还是更怕「做出来但太水」？
   │  ├─ 怕做不出来 ──→ P1（三种结果都能成文）
   │  └─ 怕太水 ─────→ P2（claim 最锋利，但措辞要小心）
   └─ 你导师要求 CCF-C 以上？
      ├─ 是 ──→ P1，且必须加 7B 的一个点（要借卡）
      └─ 否 ──→ P1，按现在的配置直接做
```
